Scryer Plugin Settings

This Alpha targets Jellyfin 10.11.x web clients and was tested against Scryer 0.19.7. Compatibility is decided by the live preflight checks below, not by a version number. Each person connects their own Scryer account; do not enter a shared Scryer API key here.
Address the Jellyfin server can reach for OAuth discovery and future server-to-server calls.
Cleartext OAuth sends authorization codes, PKCE verifiers, and rotating tokens over the network. Enable only for an isolated trusted private network; HTTPS is strongly preferred.
Browser-visible Scryer authority used for the OAuth consent redirect. It may differ from the internal URL.
Public OAuth client identifier registered in Scryer. It is not a client secret.
Public URL users return to after Scryer authorization. It must match the registered callback exactly.
Register this exact URI in the Scryer OAuth client. It is calculated from the public Jellyfin URL.

Off by default. Jellyfin stores channel items in its own library database, once per Jellyfin user, and refreshes them on the daily Refresh Channels task. Enable it only if you want the Scryer Discovery tile under My Media on TV clients.
Recently watched titles come first as "More like ..." rails of five, then Scryer's own discovery sections. The plugin publishes at most this many rails. Default 40.
Applies to Scryer's discovery sections; "More like ..." rails always hold five. Each published title becomes a library row and a downloaded poster on the Jellyfin server for the user who opens the rail. Default 20.
The overall budget per Jellyfin user. Rails are filled in order until it is spent, so this bounds what Jellyfin stores regardless of the other two limits. Default 200.
